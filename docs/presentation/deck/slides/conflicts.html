Two different 409s

Same status code, opposite meanings. Collapsing them into one error is the mistake this design exists to avoid.

409  Version mismatch

You wrote against stale data.

Every PATCH carries the card's current expected_version. Someone changed the card since you read it.

What the agent does: re-read the card, re-apply, retry. The work is still yours.

409  Claim contention

Someone else got there first.

The card was claimed between your read and your write, or it was never READY at all.

What the agent does: walk away and take a different card. Retrying is wrong.

One says try again. The other says stop. An agent that cannot tell them apart either loses work or fights another agent forever.
