One board, many projects, one credential each

Per-project isolation

export KANBAN_PROJECT_TOKENS=
  '{"demo":
    {"credentials":[
      {"token":"tok-build","role":"builder"},
      {"token":"tok-review","role":"reviewer"}]},
    "payments":"tok-pay"}'

A credential sees and touches exactly one project — and a bound credential carries exactly one role, served by the board itself. Project lists, task feeds and health metadata all narrow to it; an anonymous caller gets an empty list.

The 503 that looks like a broken board

This variable must hold valid JSON or nothing. A value like change-me fails every mutation closed, and nothing on screen explains why.

The board warns you first

/api/health carries a credential map. A project holding cards with no token entry reports as undercovered — a future 403, surfaced before it bites.

Wrong project, right token → 403 token is not authorized for project 'payments'

Demo this in two commands: list projects with one token, then try to PATCH another project's card and show the 403. If you are building a .env by hand, check this variable first — the empty-or-JSON rule is the single most likely way to arrive on stage with a board that refuses every write.
